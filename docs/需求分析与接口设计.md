# novel-agent 需求分析与接口设计书

> 版本：v0.1.0 · 日期：2026-09-17
> 本文档描述 novel-agent 系统的功能需求、接口设计和数据模型。

---

## 1. 项目概述

### 1.1 项目定位

多 Agent 智能长篇小说创作系统。以"作者主导、AI 执行"为核心理念，将长篇小说创作拆解为 11 个确定性环节，每个环节由专职 LLM 智能体生成产物、作者确认后流入下一环节，配合三层记忆 + 双路 RAG 的跨章连贯性体系，解决长篇创作中"流程失控、跨章失忆、挖坑不填"三大痛点。

### 1.2 核心用户

独立网文作者 / 小说创作爱好者（单人使用，无协作需求）。

### 1.3 系统边界

- 单机部署（后端 FastAPI + 前端 Vite 开发服务器）
- LLM 走 OpenAI 兼容接口（DeepSeek 或其他）
- 无多用户/鉴权体系（本机工具定位）
- 无分布式/消息队列（单进程多线程）

---

## 2. 系统架构

### 2.1 分层架构

```
┌────────────────────────────────────────────────────┐
│  接口层  api/routes (30+ REST)  api/tasks (SSE)   │
├────────────────────────────────────────────────────┤
│  编排层  graph/graph (11 节点 + 确认循环 + 路由)    │
├────────────────────────────────────────────────────┤
│  智能体层  agents/* (11 个专职 LLM 任务单元)        │
├────────────────────────────────────────────────────┤
│  公共能力层                                         │
│  llm/ (模型分级·容错·提示词)  memory/ (三层记忆)    │
│  rag/ (双路检索)  library/ (基础库)  revision/     │
├────────────────────────────────────────────────────┤
│  基础设施层  storage/ (路径·原子写)  types/ (契约)  │
│  config (配置)  logutil (日志)  export (导出)       │
└────────────────────────────────────────────────────┘
```

依赖方向：单向向下，无反向依赖。

### 2.2 创作流水线（11 节点）

```
stage0 选题立项 → stage1 世界观构建 → stage2 人物设定 → stage3 全书总纲
→ stage4a 卷级细纲 → stage4b 章级规划 → stage5 正文写作
→ stage6 一致性检查 → stage7 记忆更新
→ stage7 条件路由：本卷还有下一章 → 回 stage4b（章节循环）
                      本卷无更多章   → stage8 编辑终审 → stage9 导出 → END
```

每个含 LLM 的节点在生成后通过 `interrupt()` 暂停，等待作者确认（accept / edit / regenerate），确认后产物写入状态、流入下一节点。全程通过 SQLite Checkpoint 持久化，服务重启后可从最后确认点恢复。

## 3. 功能需求

### FR-1 项目管理

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1.1 | 创建项目 | 输入书名、题材（webnovel/literary/short_story）、可选自定义 ID；创建后生成双目录结构（output/projects/<id> + data/projects/<id>） |
| FR-1.2 | 项目列表 | 返回所有项目，附带实时统计（章节数/卷数/阶段/卷规划来源） |
| FR-1.3 | 查看项目 | 返回元数据（标题/题材/创建时间/当前阶段/总章数） |
| FR-1.4 | 删除项目 | 删除双目录下全部数据；仅允许删除最新一章的约束不适用此处（项目级删除无条件）；需先关闭 SQLite 连接再删文件 |
| FR-1.5 | ID 白名单 | project_id 仅允许 `[A-Za-z0-9_-]+`，防止路径穿越 |

### FR-2 创作流水线（确认流）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-2.1 | 启动流水线 | POST start：注入立意，图执行至 stage0 interrupt 暂停 |
| FR-2.2 | 确认动作 | POST confirm：三种动作——accept（接受产物）/ edit（替换产物，附 data）/ regenerate（重新生成当前产物） |
| FR-2.3 | 确认循环 | 同一节点内可多次 regenerate（重新生成一版再确认），interrupt 按调用序领答案 |
| FR-2.4 | 状态查询 | GET state：返回当前阶段/标签/载荷/卷章游标；用于前端恢复上下文 |
| FR-2.5 | SSE 事件流 | GET events：推送历史日志 + 当前确认载荷 + eof 关流 |
| FR-2.6 | Checkpoint | 全程 SQLite 持久化；服务重启后从最后确认点恢复 |
| FR-2.7 | 编辑产物 | 作者可通过 edit 动作替换产物（需通过 Pydantic Schema 校验） |
| FR-2.8 | 重新生成 | 作者可触发 regenerate，节点内循环回到生成函数重新调用 LLM |
| FR-2.9 | 设定修改 | PUT products：支持 concept / world_bible / characters / outline / volume_plans / techniques / narrative_blueprint 七个字段 |

### FR-3 章节生成（旁路）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-3.1 | 提交生成 | POST volumes/{vol}/chapters：按卷设定+讨论要点+自定义指令生成正文预览（未保存）；支持 agentic 开关（智能研究模式） |
| FR-3.2 | 接受章节 | POST chapters/{vol}/{ch}/accept：将 pending_chapter 写入 chapters，触发记忆更新 |
| FR-3.3 | 放弃章节 | DELETE chapters/{vol}/{ch}：清除 pending_chapter |
| FR-3.4 | 修改章节 | PUT chapters/{vol}/{ch}：编辑正文后保存 |
| FR-3.5 | 按讨论重生成 | POST volumes/{vol}/chapters/{ch}/regenerate：基于聊天讨论的改写方向重写已有章节（支持 agentic 开关） |
| FR-3.6 | 定点改写场景 | POST chapters/{vol}/{ch}/scenes/{scene}/rewrite：只重写指定场景，其余字节级保留；支持空指令自由重写 |
| FR-3.7 | 删除已保存章节 | DELETE volumes/{vol}/chapters/{ch}：仅允许删除全书最新一章（防止编号错乱与记忆断层） |

### FR-4 三层记忆与连贯性

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-4.1 | 短期记忆 | 最近 N 章（默认 5）完整正文注入写作 prompt；截断保尾（最新章结尾最重要） |
| FR-4.2 | 中期记忆 | 每章接受后生成 LLM 摘要（80-150 字）；写作时注入本卷已写章摘要 + 前几卷卷摘要（分层） |
| FR-4.3 | 长期记忆 | 场景正文切片存入向量库（bigram/语义双模可插拔）；写作前按角色名检索 top_k 相关片段 |
| FR-4.4 | 人物状态卡 | 每章写完后自动提取主要角色状态增量（位置/情绪/知道什么/目标进展/弧光阶段）；注入下一章写作 prompt |
| FR-4.5 | 时序知识图谱 | 每章写完后抽取人物关系边（带章节号），查询按章过滤防泄露未来 |
| FR-4.6 | 卷摘要聚合 | 卷完成时自动聚合本卷全部章摘要为卷级摘要（cheap 模型）；注入跨卷写作上下文 |

### FR-5 写作手法库

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-5.1 | 四类基础库 | 性格库 / 小说工具库 / 人物模板库 / 写作手法库，各自独立 CRUD |
| FR-5.2 | 手法分级 | knowledge（guidance 注入 prompt）/ mechanism（含 structure_schema，触发流水线行为） |
| FR-5.3 | 手法挂载 | 项目可动态挂载/卸载手法（快照写入图状态）；按 apply_stage 路由注入（规划期/写作期/检查期） |
| FR-5.4 | 叙事蓝图 | 机制型手法"暗线设计"的结构化数据：主题/意象/暗线列表（真相/表象/揭示计划/关联人物）；可 AI 生成 + 手动编辑 |
| FR-5.5 | 暗线揭示纪律 | 写手知真相但被禁止点破；每章至多 1-2 处自然暗示；一致性检查对照纪律核查剧透 |
| FR-5.6 | 项目隔离 | 故事内容（正文/记忆/图谱/状态卡）按项目硬隔离；基础库跨项目共享 |

### FR-6 对话式创作

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-6.1 | 多场景对话 | 每个环节独立对话：concept / world / characters / outline / volume_N / chapter_N_M |
| FR-6.2 | 上下文接地 | 章节助手注入近5章全文+摘要+状态卡+RAG；卷助手注入前情摘要+账本+卷弧；总纲助手注入立项书+世界观+蓝图+账本 |
| FR-6.3 | 对话历史持久化 | 对话按场景持久化为 JSON 文件（原子写）；清空对话重置 |
| FR-6.4 | 讨论要点提炼 | 生成时自动提炼聊天讨论为设计要点注入写手 prompt |

### FR-7 工程化

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-7.1 | 后台任务 + SSE | 长耗时生成在后台线程执行，SSE 流式推送各阶段进度事件 |
| FR-7.2 | 断线重连 | 前端 SSE 断线指数退避重连（1s→15s，≤6 次）；服务端正常 eof 不重连 |
| FR-7.3 | 删除章节守卫 | 仅允许删除全书最新一章（防止编号错乱与记忆断层） |
| FR-7.4 | 路径穿越防护 | project_id 白名单 + chat_context 白名单（双层咽喉点校验） |
| FR-7.5 | JSON 原子写 | 所有状态文件写入走 tempfile + os.replace |
| FR-7.6 | 成本计量 | 按 LLM 响应 usage 分模型分桶累积 token，查询时按模型单价计算费用 |
| FR-7.7 | mock 双轨 | 环境变量 NOVEL_ENGINE_MOCK=1 切换全链路确定性 mock，测试零 token 成本 |

## 4. 接口设计

### 4.1 项目管理

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|---|---|---|---|---|
| POST | /api/projects | 创建项目 | `{title, genre, project_id?}` | `{project_id, title, genre, dirs}` |
| GET | /api/projects | 项目列表（实时统计） | — | `{projects: [{project_id, title, genre, stage, chapters, volumes}]}` |
| GET | /api/projects/{id} | 项目元数据 | — | `{project_id, title, genre, created_at, current_stage, total_chapters}` |
| DELETE | /api/projects/{id} | 删除项目（含全部数据） | — | `{deleted: id}` |

### 4.2 创作流水线

| 方法 | 路径 | 说明 | 请求体 | 响应 |

| PUT | /api/projects/{id}/products | 修改设定 | `{field, value}` | `{ok, field}` |

## 5. 数据模型

### 5.1 图状态（NovelState）

| 字段 | 类型 | 说明 |
|---|---|---|
| project_id | str | 项目 ID |
| project_root | str | 项目根路径 |
| genre | str | 题材 |
| title | str | 书名 |
| user_idea | str | 初始立意 |
| current_stage | str | stage0…done |
| concept | dict | 立项书 |
| world_bible | dict | 世界观设定库 |
| characters | list[dict] | 人物档案列表 |
| outline | dict | 全书总纲 |
| volume_plans | list[dict] | 卷规划列表 |
| writer_packets | dict | {vol_ch: packet} |
| chapters | dict | {vol_ch: chapter} |
| current_volume / current_chapter | int | 章节游标 |
| consistency_report | dict | 最近一致性报告 |
| character_state | dict | 人物状态卡 {entries: [{character_id, name, location, mood, …}]} |
| writer_proposals | dict | 写手记忆提案（stage7 消费后清除） |
| narrative_blueprint | dict | 叙事蓝图 {theme, motifs, dark_threads} |
| techniques | list[dict] | 挂载的手法快照 |
| memory_notes | list[str] | 记忆更新日志 |
| editorial_report | dict | 终审报告 |
| final_paths | list[str] | 导出文件路径 |
| messages | list[str] | 流水线日志 |

### 5.2 关键 Schema

**Concept**：title_idea / logline / core_selling_point / target_readers / word_count / volumes / tone / red_lines

**Character**：id / name / role / tier / motivation / flaw / arc / relationships / timeline / appearance / voice / habits / background / signature_item

**WriterPacket**：volume / chapter / title / goal / conflicts / hook / beats / foreshadow / characters / pov / reference_seeds

**Chapter**：volume / chapter / title / scenes[]（id / heading / text / paragraphs）

**ConsistencyReport**：chapter / issues[]（severity/kind/location/description/fix_action/resolved）/ needs_human / auto_fix_attempts

**NarrativeBlueprint**：theme / motifs / dark_threads[]（id/name/truth/surface/reveal_plan/related）

**CharacterState**：entries[]（character_id/name/tier/status/location/mood/health/knowledge/goal_progress/arc_stage/last_chapter）

## 6. 非功能需求

| 编号 | 需求 | 实现方式 |
|---|---|---|
| NFR-1 | 安全 | project_id 正则白名单；chat_context 白名单；CORS 白名单；.env 隔离 |

| NFR-5 | 可扩展 | 模型四档可配置；embedding 可插拔；Agent 工厂函数可扩展新节点 |

## 7. 约束与取舍

| 决策 | 理由 |
|---|---|
| 单机部署（无分布式/鉴权） | 个人工具定位，多实例/鉴权在产品化时补充 |
| 检索默认 bigram 回退 | 零依赖离线可测；embedding 为可插拔升级项 |
| 章规划防剧透裁剪 | 防止模型把后文真相提前泄露进正文 |
| 记忆更新走提案制 | 写手不可信，提案校验后合并防记忆污染 |
| 删除仅限最新章 | 防止中间章编号错乱与记忆断层 |
| 同步 LLM 调用（无流式 token） | 结构化输出（json_object）不支持流式；进度用 SSE 阶段事件替代 |
