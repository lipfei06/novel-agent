# 本地模型使用指南

> 适用版本：支持 Ollama / LM Studio / vLLM / llama.cpp server 等一切 **OpenAI 兼容**服务。
> 无需改任何业务代码——项目对模型的全部访问都走 `llm/factory.py` 的 OpenAI 兼容协议。

---

## 1. 为什么可以直接接本地模型

- 生成/抽取全部走 `ChatOpenAI(base_url=...)`，**换厂商=改 base_url**；
- `api_key` 缺失时工厂自动用占位符（本地服务不校验）；
- 结构化输出自带降级：服务端不支持 `response_format=json_object` 时**自动退回纯提示词约束**，不影响流程；
- embedding 不配置则回退内置 bigram 检索，配置了 OpenAI 兼容 `/embeddings`（Ollama/LM Studio 均提供）即升级语义检索。

## 2. 三步接入（以 Ollama 为例，本机已验证）

```bash
# 0) 关键：调大 Ollama 上下文（默认 4k 会静默截断长章节！）
set OLLAMA_CONTEXT_LENGTH=32768   # Windows；然后重启 ollama serve

# 1) 模型（本机已有即可跑：gemma4:e4b 写作主力 + deepseek-r1:7b 备用审校）
ollama pull bge-m3          # 可选：语义检索 embedding（不拉则回退内置 bigram）

# 2) 复制示例配置（已按本机 gemma4:e4b 调好）
cp config.local.example.yaml config.yaml

# 3) 启动
start.bat                    # 或 python -m novel_agent.cli.app serve --port 8000 --root .
```

`config.local.example.yaml` 已按本机库存调好：四档 `gemma4:e4b` 指向 `http://127.0.0.1:11434/v1`、`deepseek-r1:7b` 备选 editor 档（`<think>` 思考段系统已自动剥离）、本地 embedding 配置。LM Studio 改端口 `1234/v1`，vLLM `8001/v1`。

## 3. 任务级模型路由（自由切换的关键）

`config.yaml` 顶层可配 `model_overrides`：把**指定任务**路由到**指定档位**，切换模型只改配置，不动代码：

```yaml
llm:
  cheap:  { model: "deepseek-chat", ... }   # 默认云端
  local:  { model: "gemma4:e4b", base_url: "http://127.0.0.1:11434/v1", api_key_env: "", ... }

model_overrides:
  summary: local        # 章/卷摘要 → 本地模型（每章省一次云端调用）
  # 还可扩展: relations / states / consistency 等任务名
```

- 已接入的任务名：`summary`（章/卷摘要，`memory/mid_term.py`）；
- 未配置 override 的任务走各自默认档位；override 指向的档位不存在时回退默认档位；
- 调用侧用法：`get_chat_model("cheap", cfg, task="summary")`。

## 4. 关键参数怎么调

| 参数 | 建议 | 原因 |
|---|---|---|
| `token_budget.write` | 模型窗口 × 0.5 以内 | write 阶段注入最多（窗口+RAG+任务书） |
| `memory.short_window / full_window` | 8k 窗口→1；32k 窗口→2/1 | 窗口是最大单项注入 |
| `rag.top_k` | 2~3 | 本地上下文有限，宁少勿滥 |
| 模型档位 | cheap 用 7B，writer ≥14B | 抽取类任务小模型足够 |

判断口诀：**write 预算（字符）≤ 模型上下文 token 数 × 1.5**（中文 1 字≈1 token，留一半给输出和余量）。

## 4. 兼容性说明

- **json_object 自动降级**：`invoke_structured` 首次遇到 `response_format` 不支持类报错时，自动去掉服务端 JSON 约束、仅靠提示词+客户端校验继续（不消耗重试次数，日志可查）。**本机 gemma4:e4b 实测 json_object 可直接使用，端到端结构化输出链路已验证**。
- **推理类模型（deepseek-r1 等）输出带 `<think>` 思考段**：提取前系统已自动剥离，可放心用于 editor 档；不建议用于 writer 档（思考段消耗输出配额）。
- **embedding 缺失**：`memory.vector.embedding` 不配置 → 向量库自动回退 bigram 模式（离线、零成本、无语义泛化）。
- **切换 embedding 模式会清空旧向量**：属预期行为，接受后重新生成章节即可重建。

## 5. 验证清单

1. `curl http://127.0.0.1:11434/v1/models` 能列出模型；
2. 后端日志无 "json_object" 相关报错（或已看到自动降级）；
3. 生成一章，检查 `data/projects/<id>/cost.json` 有 tokens 记录；
4. （可选）配置 embedding 后，`vector_stores/long_term.json` 的 `mode` 字段变为 `dense`。

## 6. 已知边界

- 本地 7B 模型的 JSON 遵循度明显弱于 DeepSeek：结构化输出失败重试会更频繁（容错链兜底，但产出质量下降），建议抽取类（cheap 档）用 14B 以上；
- 长篇（>10 章）建议上下文 ≥32k 的模型，否则窗口频繁触发预算守卫；
- `deepseek-*` 云端模型与本地模型可混用：四档里任意几档指向云端、其余本地（如 writer 用云端保质量、cheap 用本地省成本）。
