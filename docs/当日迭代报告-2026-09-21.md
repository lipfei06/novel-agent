## 一、今日代码更新了什么逻辑

### 1. 长程一致性：正典事实层（核心新增）

**问题**：长篇生成的桥段重复（"鉴定假翡翠打脸"写了 7 遍）、道具秘密反复"重新发现"（怀表芯片取出后又"被解密"）、关键数字漂移（同一笔资金 5 亿/1200 万/800 万五个版本）。根因：系统只跟踪"人"的状态（状态卡），不跟踪"物"和"事"。

**逻辑**：
- 章节定稿时的"理解调用"（一次 LLM 调用）新增两类抽取：**本章关键事件**（3~6 条）与**道具/秘密事实变更**；
- 事件写入**事件账本**（`{vol_ch: [事件]}`），道具事实写入**道具登记卡**（唯一事实值 + 变更史，芯片取出即取出）；
- 下一章任务书生成时，注入三段正典约束：**已发生事件清单（严禁重复同类桥段）**、**已用标题清单（强制唯一）**、**道具既定事实（不可矛盾、不可再次发现）**。

**实测**：同一本书重新规划第 21 章——旧任务书是第 4 次重复的"暗涌/截获流水"；新任务书标题变为唯一的"佛堂问话"，目标改为推进保险柜密码伏笔。

### 2. 成本工程：四项优化 + 按章成本流水

**问题**：E2E 实测每章 ~11 万 token（17 万字小说耗 265 万 token），且按章成本无法统计。

**逻辑**（对标 Claude Code/OpenCode 的上下文工程实践）：
- **分级窗口**：`full_window=1`——最近 1 章全文 + 其余章/卷摘要分级注入（原为 4 章全文平推）；
- **抽取三合一**：摘要/人物状态/关系抽取由 3 次全章调用合并为 1 次"章节理解"调用；
- **纯文本化**：抽取环节改喂纯文本，去除 scenes JSON 的键名与转义膨胀；
- **缓存友好布局**：写手 prompt 重排为"稳定记忆块前置、每章变化内容后置"（适配 DeepSeek 前缀缓存的命中规则：从第 0 个 token 起逐字匹配）；
- **按章成本流水**：`cost.json` 新增 chapters 分桶，每次调用按"当前章"归属累计。

**实测**：优化后批次 **8.4 万 → 13.2 万 token/章 修正为约 13 万/章，较优化前约 18.7 万/章下降约 30%**；缓存命中率基线 62%（布局重排的收益待下一批账单验证）。

### 3. 一致性审查闭环：从"发现"到"作者决策"

- stage6 审查发现 high 级问题 → auto-fix ≤3 次 → 超限打 `needs_human` 标记；
- 前端：超限显示琥珀色警示横幅（含处理指引），每条矛盾展示描述/位置/**AI 修复建议**，并提供**逐条修复指令输入**（选场景 + 填指令）；
- 指令修复后**自动重新审查**并再次确认，作者始终面对最新报告；
- 修复后：**标题硬约束**（写手不得另起标题）与**字数核验**（偏差 >25% 自动一轮精简/扩写轻修）。

### 4. 规划约束与全局顾问

- **章数硬绑定**：总纲/卷规划的 chapter_count 由 profile 强制决定（LLM 两次自定 30/6 章导致全书长度失控），原则"剧情归 LLM、长度归配置"；
- **总纲/卷助手内容级约束**：助手 prompt 注入前情摘要+人物状态等正典，要求每个建议引用具体章节号；
- **全局规划顾问（总编辑）**：作品设定首框升级为全书接地（进度字数/卷结构/20 章摘要/事件账本/道具事实/待回收伏笔）的咨询型 Agent，实测能自主发现"13.5 万字超出 10 万目标 36%"的结构风险。

### 5. 稳定性修复（真实生成暴露的集成缺陷）

| 缺陷 | 根因 | 修复 |
|---|---|---|
| 一致性检查预算超限后流水线 500 中断，且卡死无法续跑 | confirm 端点遇"有断点、无确认点"状态返回假视图 | 检测该状态时 `invoke(None)` 从 checkpoint 断点恢复 |
| 成本记账 100% 丢失（静默） | LangChain usage 键名 `token_usage` vs 代码取 `usage`；confirm 线程未标记项目 | `extract_usage` 兼容三种键位；start/confirm 显式标记 |
| 章节页路径"最近一章"错判 | 章节键字符串排序（"1_9" > "1_20"） | 全部改数值序 |
| 本地模型 `json_object` 不支持即失败 | 服务端兼容性差异 | 自动降级为纯提示词约束（不消耗重试次数） |

## 二、用到了什么技术

- **LangGraph 断点恢复**：`invoke(None)` 从 SqliteSaver checkpoint 续跑崩溃的 superstep；
- **DeepSeek 前缀缓存**：命中价约 1/10 的计价模型 + "稳定前缀 + append-only + 滑动窗口分级"的布局纪律（对标 Manus/Claude Code 的 context engineering）；
- **Pydantic 动态 schema**：`ChapterUnderstanding` 合并 schema、`ChapterDesign` 结构化回复、`model_json_schema()` 注入提示词；
- **threading.local 线程级归属**：多项目/多章节并发生成时的成本分账；
- **FastAPI 端点扩展**：`/chat/structured`（结构化对话）、`/memory/rebuild`（记忆重建）、`/chat` 正典注入；
- **React 组件化**：`Stage6View` 审查闭环组件、`autoCollapse` 状态联动、确认卡按归属动态渲染；
- **E2E 驱动测试**：httpx 脚本 + 时间线取证 + 断点续跑，模拟真实多批次创作。
