# 成本优化需求分析——分级窗口 / 抽取合并 / 缓存布局

> 版本：v1.0 ｜ 日期：2026-09-21 ｜ 状态：已评审，进入实现
> 背景：E2E 真实生成实测（docs/e2e-测试报告-真假千金十万字.md）——7 章消耗 173 万 tokens（应用内口径；控制台口径 285 万含修复前未记账部分），缓存命中率 62%，放大率约 70 token/正文字。
> 对标：Claude Code / Codex / OpenCode 的成熟实践——分级压缩（compaction + keep.tokens）、按需检索、缓存友好布局、合并调用。

---

## 1. 问题定量

| 消耗源 | 机制 | 占比估计 |
|---|---|---|
| 短期窗口 | 每章写作注入最近 4 章全文（2.5~3 万字符），逐章累积 | 单次调用最大项（>50% 写作输入） |
| 正文重复计费 | 同一章正文以完整 JSON 喂给 摘要/状态卡/关系抽取/一致性/下章窗口 共 5~8 次 | 累计放大 ~3 倍 |
| JSON 结构开销 | scenes 数组键名/转义，比纯文本膨胀 30~50% | 抽取环节全部受影响 |
| 缓存未命中 | 写手 prompt 以每章变化的 packet 开头，2 万字窗口被挤出缓存前缀；滑动窗口天然破坏前缀 | 输入费 38% 按全价计 |

## 2. 改造项

### OPT-A 分级窗口（全文降级为"最近 1 章全文 + 其余摘要"）

| 项 | 内容 |
|---|---|
| 现状 | `memory.short_window=4`：4 章全文无差别注入 |
| 目标 | 新增 `memory.full_window`（默认 1）：仅最近 N 章全文；更早章节由既有章摘要/卷摘要承担（`_build_writing_context`/`_memory_context` 已有摘要注入通道，只需把排除集与全文窗口对齐） |
| 保真 | 最近 1 章全文天然覆盖"上章结尾"，衔接处无损失 |
| 兼容 | `short_window` 保留但降语义为摘要覆盖参照；旧配置不报错 |

**验收**：write 阶段估算输入从 ~60k 字符降至 ~35k 以下；正文质量抽查无明显连贯性退化。

### OPT-B 抽取三合一（摘要/状态/关系 → 一次调用）

| 项 | 内容 |
|---|---|
| 现状 | `summarize_chapter`、`extract_character_states`、`extract_relations` 三次独立调用，各自携带全章 |
| 目标 | 新增 `agents/understanding.py::understand_chapter(chapter, characters, prev_entries, cfg)` → 一次调用输出 `ChapterUnderstanding{summary, character_state, relations}`；`update_chapter_memory` 与 stage7/`_finalize_chapter` 改为分发理解结果 |
| 兼容 | 旧函数保留（mock 测试依赖）；mock 模式下 `understand_chapter` 复刻原三者的确定性输出，端到端行为不变 |
| 产出复用 | `CharacterState` schema 直接复用；relations 复用 Relation 结构 |

**验收**：定稿一章仅 1 次 LLM 抽取调用（原 3 次）；state/relations/摘要内容与合并前语义一致；既有测试全绿。

### OPT-C 抽取环节纯文本化

| 项 | 内容 |
|---|---|
| 现状 | 章节以 `json.dumps(chapter)` 进入摘要/状态/关系 prompt（scenes 键名+转义，膨胀 30~50%） |
| 目标 | 统一使用"标题行 + 【场景标题】正文"纯文本格式（新增 `chapter_plaintext(chapter)` 工具函数，三处共用；OPT-B 的合并调用同样使用） |
| 范围 | 仅抽取类环节；写正文的结构化输入输出不变 |

**验收**：抽取 prompt 字符量下降 ≥25%；输出字段不变。

### OPT-D 写作 prompt 缓存友好重排

| 项 | 内容 |
|---|---|
| 现状 | `generate_chapter` 的 user 消息以每章变化的 packet 开头，2 万字窗口被挤出缓存前缀（实测命中率 62%） |
| 目标 | 重排为：`<memory>`（摘要在前、全文按最老→最新排列，追加位在尾部）→ `<reference>` → packet → 指令。滑动内容集中在尾部，跨章共享前缀最大化 |
| 说明 | 滑动窗口无法做到 100% 缓存友好（滑出即失配）；本项收益为"同章重试/复查命中 + 失配点后移"，与 OPT-A 的内容缩减叠加 |

**验收**：prompt 组装顺序符合上述布局；DeepSeek 控制台缓存命中率后续批次观察（目标 >75%）。

## 3. 预期收益

| 指标 | 优化前 | 预期 |
|---|---|---|
| 每章 token 消耗 | ~25 万（含修复波动） | ~12~15 万 |
| 每章估算成本 | ~¥0.4~0.6 | ~¥0.2~0.3 |
| 十万字全书 | ¥12~18 | **¥6~9** |
| 缓存命中率 | 62% | 75%+ |

## 4. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 窗口降到 1 章全文后连贯性退化 | 上章全文完整保留衔接；章摘要+卷摘要兜底；生成后抽查 |
| 合并调用输出过长被截断 | state 条目限定主要角色；max_tokens cheap 档 4096 足够（summary 150 字 + 关系≤5 + 状态卡） |
| 重排影响写作质量 | prompt 内容不变只变顺序；回归对比第 8 章前后生成质量 |
| 旧配置/旧测试不兼容 | full_window 有默认值；旧函数签名不变 |
