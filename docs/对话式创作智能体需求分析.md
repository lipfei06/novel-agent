# 对话式创作智能体 需求分析与设计（对话层+规划层合并）

> 版本 v1.0 ｜ 状态：已评审，分期实施
> 背景：章节助手（对话层，cheap 档）与规划师/规划研究（规划层，creative 档）当前是割裂的两层——作者说"直接写"时意图被绕道翻译，规划过程作者不可见，检索无判断。

---

## 1. 问题定性

| # | 问题 | 根源 |
|---|---|---|
| 1 | 聊天里的写作意图被当聊天回复 | 章节助手无生成触发能力，意图断在对话层（写作意图直通 ef6569f 已部分修复：命中正则即触发任务，但规划过程仍不可见） |
| 2 | 每章无条件 RAG 检索，无法判断"要不要查、查到的好不好" | 检索决策硬编码，无模型参与 |
| 3 | 规划与正典脱节 | 规划师只"读"正典注入文本，无主动查证能力 |

## 2. 目标形态（合并后的对话式创作智能体）

**一个智能体贯穿章节全生命周期**：与作者对话（收集意图）→ 自主查证（ReAct 工具循环）→ 拟任务书（作者可干预）→ 触发生成（流式）→ 预览审阅。全程在「新建章节」页一个界面内完成，**对话即规划、规划即生成**。

```
作者：这章揭怀表的秘密，但留个尾巴
智能体：💭 先核实伏笔原文…… 🔍 命中第1章、第12章
智能体：📋 任务书拟定：目标=解密芯片、钩子=黑车跟踪 —— 这样走行不行？
作者：行，开写
智能体：任务书已定稿 → 交给写手 →（流式生成）→ 预览
```

## 3. 分期实施

### 第一期（路线 B）：研究循环搬进生成任务 + 规划过程镜像进对话

| 项 | 内容 |
|---|---|
| 生成任务挂规划研究 | `react_enabled` 时，章节页生成任务先跑 planner_research 研究循环（**非交互**：澄清问题作为"开放问题"注入研究 prompt，不挂起），digest → 任务书 research_context |
| 规划过程镜像 | 研究循环每轮的 Thought/Action/Observation 作为进度事件推送，前端聊天面板以助手消息渲染——**作者实时看到智能体在查证什么** |
| 非交互澄清 | clarify 产生的开放问题不挂起，并入研究 prompt 作为"按默认项假设作答"的输入 |

### 第二期（路线 A）：对话智能体工具化

| 项 | 内容 |
|---|---|
| 触发 | 章节助手聊天中命中写作意图（"直接写/开写/可以写了"）→ 不再走写作意图直通，而是进入**对话内 ReAct 规划** |
| 对话内循环 | 智能体在聊天流中：Thought（可见）→ 只读工具查证 → 观察 → …… → 产出任务书 → 询问作者确认 → 触发生成 |
| 边界 | 工具仍全只读；对话内循环 ≤2 轮；正文生成仍走独立任务（不进对话） |
| 降级 | react 关闭时维持现行"意图直通+单发规划" |

### 分期理由

第一期把"规划过程可见+查证接入生成"落地（复用 stage4r 的循环代码，改动小）；第二期把"对话本身变成 Agent 循环"（涉及聊天后端协议扩展：消息流新增 tool 类型、前端渲染），量大但价值在于**作者全程与同一个智能体对话，无界面切换**。

## 4. 技术设计

### 4.1 章节生成任务挂规划研究（第一期）

```
POST generate-task（react_enabled 时）
  → clarify_with_author(...)          # 判断开放问题（不挂起）
  → 开放问题并入研究 prompt（"以下问题暂按默认项假设，作者后续可修正"）
  → run_planner_research(answers=None)  # 只读查证循环
  → digest → research_context → 任务书 prompt
```

### 4.2 规划过程镜像（第一期）

任务进度事件新增 `research` 类型：每轮的 Thought 与查证动作/结果摘要。前端聊天面板渲染为助手消息（灰底斜体），与生成进度条并存。

### 4.3 对话内 ReAct 规划（第二期）

章节助手升级为工具增强智能体：
- 工具集 = 规划研究循环同款 6 个只读工具；
- 作者消息命中写作意图 → 智能体进入规划模式：聊天流内逐轮输出 Thought + 查证动作（渲染为过程消息），查证充分后产出任务书 → 询问作者确认 → 触发生成；
- 非写作消息仍走普通对话回复（意图门控：显式按钮 + 意图分类双通道）。

---

## 5. 成本与风险

| 项 | 估算 |
|---|---|
| 第一期每章增量 | 研究循环 1~3 轮 cheap/creative 调用 ≈ +2~8k token |
| 第二期每条消息增量 | 对话消息升 creative 档（×3~5），规划模式另计 |
| 风险：聊天档位上升成本 | 意图门控确保只有写作相关消息进 creative |
| 风险：工具循环失控 | 轮数/条数硬上限 + 只读工具 |

---

## 6. 验收标准

1. 第一期：生成任务进度流出现规划查证事件（Thought+Action+Observation），前端聊天面板可见；
2. 第二期：章节助手聊天中说"直接写" → 智能体在对话内完成查证与规划，产出任务书并触发生成；
3. 既有流程零回归（159+ 测试全绿）；mock 模式全程确定性。
